# Concern-to-brief media

Record the connected workflow after verification: a concern becomes evidence, an optional concept, and a discussion brief. The earlier capture-only direction obscured the original product outcome. Existing footage remains explicitly labeled as the earlier interface until a replacement is recorded.

## Primary deliverable

A 30–40 second silent product walkthrough, plus a matching still poster from the same recording. Show the current white/charcoal interface at a readable size, with brief captions and deliberate cuts. User-controlled playback, no loop, no autoplay.

| Shot | Duration | Visible action | Caption |
| --- | --- | --- | --- |
| Locate | 0–5s | Choose a precise street location; select Mark a problem | Mark the spot |
| Document | 5–11s | Add a photo and confirm the location label | Show what you noticed |
| Describe | 11–17s | Enter a short note and select a problem type, or Other | Add the details |
| Connect | 17–22s | Save observation, then select Explore a change here; show the carried-forward concern | Keep the evidence together |
| Explore | 22–30s | Choose an approximate layout and a concept; show assumed dimensions and a concrete allocation change | Make the choices visible |
| Brief | 30–38s | Add a requested next step, prepare the PDF, show its opening page | Bring something to the discussion |

The poster should show the actual brief beside the place it concerns. Reuse the existing satellite screenshot as earlier map footage if useful. An evidence-only brief is an equally valid outcome when no redesign is needed.

## Capture conditions

- Record in the local demo with analytics and the live backend disabled. Keep example/session labels visible and label the final asset as a demonstration. Never publish a fabricated observation.
- Use a real, permissioned problem photo when available. An illustrative photo must be explicitly labeled; it must not be presented as evidence of a problem at the selected location.
- Use a fixed, non-personal example location and coherent example text. New live reporters need a photo; the demonstration should include one.
- Retain map-provider attribution. Do not crop out required credits.
- Capture after UI transitions and map tiles settle. Cut loading pauses; retain the actual action order.
- The recording must not depict city forwarding, repairs, verified hazards, or community participation that did not occur.

## Delivery and verification

Export H.264 MP4 with fast-start metadata; retain the source recording. Produce one landscape landing asset and a portrait version only if needed for mobile promotion. Verify playback, keyboard controls, readable mobile layout, and matching poster/caption. Update the landing caption to describe the connected workflow and remove the earlier-interface caveat only when the footage actually matches the shipped interface. No new recording has been produced as part of this implementation.
